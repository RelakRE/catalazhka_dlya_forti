# Intel-сборка и публикация

Для сборки: Intel Mac, Xcode Command Line Tools со Swift/AppKit и Python 3.
Для запуска готового `.app` эти инструменты не нужны.

```sh
python3 -B build_app.py
```

Результат: `dist/Forti Split Intel.app`. Существующий пакет не перезаписывается:
выберите другой `--output`, если он уже есть. Сборка явно targeting x86_64,
macOS 13; минимальная версия не означает подтверждённую приёмку на ней.

Скрипт скачивает **зафиксированный** Intel CPython из официального проекта
Astral python-build-standalone и сверяет SHA-256 из `runtime-lock.json`.
Лицензии загружаются по закреплённому commit ID. Во время запуска приложения
загрузок runtime нет. `--runtime-archive <путь.tar.gz>` позволяет использовать
ранее загруженный архив; проверка SHA-256 остаётся обязательной.

В пакет всегда помещается пустой профиль — рабочая конфигурация из checkout
не встраивается. Перед публикацией проверяйте также документацию, тесты,
бинарные строки, архив, ресурсы и историю. Старую приватную историю нельзя
публиковать через push --all или push --tags.

## Подпись

По умолчанию подписываются ad-hoc все Mach-O runtime и затем приложение.
Это только тестовый вариант, не Developer ID и не одобрение Apple.
Проверка `codesign --verify --deep --strict` проверяет целостность, не Gatekeeper.

При наличии собственного сертификата:

```sh
python3 -B build_app.py --identity 'Developer ID Application: YOUR NAME (TEAMID)'
```

Скрипт использует hardened runtime и timestamp. После этого отдельно выполните
notarization через `xcrun notarytool` с собственными учётными данными, проверьте
Accepted и прикрепите ticket (`stapler`) **до** упаковки окончательного ZIP.
Подписанный путь сборки ещё требует отдельной проверки: наличие аргумента
`--identity` само по себе не доказывает принятие Apple.
Не храните сертификаты, ключи и пароли в репозитории.
[Документация Apple](https://developer.apple.com/developer-id/).

В 1.3.0 пакет содержит `build-metadata.json` с относительными именами исходников
и SHA-256, без личных путей. UI-тест записывает версию и хеш именно запущенного
исполняемого файла: результат от другой сборки нельзя принимать за текущий.
Рабочий pipeline дополнительно сравнивает `.py`/Swift с чистым коммитом,
прогоняет тесты встроенным Python и проверяет ZIP после распаковки.
Эти проверки предотвращают случайное смешение артефактов, не заменяют подпись
издателя или независимый аудит.

Локальная VFS-накладка при обнаружении дублирующего SwiftBridging module map
используется только компилятором; SDK/CLT на диске не меняются.

Иконка — собственный векторный рисунок в `AppIcon.swift`. Во время сборки AppKit
создаёт PNG всех размеров для iconset, затем штатный `iconutil` собирает
`FortiSplit.icns`. Файл включается в Resources и указывается в `CFBundleIconFile`
до подписи пакета. Загрузки изображений и отдельные утилиты при запуске не нужны.

## Локальная и публичная история

Публичный репозиторий начинается с отдельного очищенного root-коммита.
Проверенная первая Terminal-версия и её исходная история остаются в приватной
локальной копии, а не становятся предками публичных коммитов.

Приватные профили, отчёты, кэш, runtime-архивы и локальные сборки не коммитятся.
Готовый ZIP публикуется отдельным asset в Releases вместе с SHA-256 и честным
статусом предварительной приёмки. SHA-256 из того же релиза защищает от случайной
порчи; он не заменяет доверенную подпись издателя.
