# Переносимость и граница Windows-порта

## Текущая архитектура

```text
Нативный интерфейс macOS (AppKit)
             │ JSON: статус и один следующий шаг
desktop_entry → platform_contract → platform_adapters
             │                         ├─ macOS → gui_backend → проверенный guardian
             │                         └─ Windows/прочие → явный отказ, без OS-команд
             ├─ setup_flow: чистый мастер состояний
             ├─ profile_model: чистый формат/валидация IPv4-профиля
             └─ json_codec: однозначный JSON
```

Переносимые модули не импортируют fcntl, AppKit, Unix-сокеты, shell-команды или
root-службу. `profile_store` — отдельный **macOS/POSIX** адаптер хранения, а не
готовое Windows-хранилище. Unix-guardian также остаётся явно платформенным.
`DesktopBackend` задаёт точку диспетчеризации; Windows-адаптер пока возвращает
`supported: false`. Это основа порта, **не Windows-приложение**.

Тест переносимого ядра отдельно: `python -B -m unittest -q test_portable_core`.
В текущей работе он выполнен на Intel Mac; реальный Windows CI/ноутбук ещё не
использовался. Эмуляция выбора платформы не равна испытанию на Windows.

## Что потребуется Windows-адаптеру

1. Свой UI, использующий тот же профиль и состояния мастера; Swift/AppKit не
   переносится напрямую. Выбор Windows UI-технологии остаётся отдельным решением.
2. Раздельные UI и узкая привилегированная Windows-служба с явным UAC при установке.
   Не передавать пароль в UI и не исполнять PowerShell/cmd из профиля.
3. Маршруты через Windows IP Helper API с InterfaceLuid/Index, метриками и
   точным владением записями. Не подставлять Windows имена в нынешний Mac spec.
4. Аутентифицированный локальный IPC: явная DACL для службы и нужного SID,
   запрет удалённых клиентов, проверка identity/результата impersonation. Default
   DACL named pipe нельзя считать эквивалентом сокета 600: она может быть шире.
5. Windows ACL для профиля/журнала; транзакционное восстановление после сбоя,
   обрыва UI, смены сети и перезапуска службы.
6. Новое обнаружение FortiClient/VPN, отдельный подписанный Windows runtime и
   Authenticode-поставка. Новые интеграционные/сетевые тесты с реальным Windows VPN.

## Матрица текущей поддержки

| Условие | Поведение / статус |
| --- | --- |
| Intel Mac, macOS 14 | Локальная сборка/автотесты/UI проверены; новая GUI VPN-приёмка остаётся ручной |
| macOS 13 и другие более новые macOS на Intel | Заявленный минимум 13, но конкретные версии требуют приёмки; не обещаем универсальность |
| macOS 12 и старше | Не поддерживается этим GUI-выпуском |
| Windows / Linux / Apple Silicon | Нет готовой версии; Windows имеет только каркас безопасного отказа, Rosetta не проверялась |
| Wi-Fi или Ethernet с именем enN | Интерфейс/шлюз определяются динамически, en0 не зашит в маршрутный spec |
| VLAN/bridge/PPP, IPv6-only, без обычного IPv4-шлюза | Безопасный отказ, а не попытка угадать маршрут |
| FortiClient SSL VPN с однозначным utun/IPv4-сервером | Текущий поддерживаемый механизм; разные версии/EMS требуют проверки |
| IPsec, несколько VPN/неоднозначный VPN | Применение не разрешается; мастер показывает причину |
| Нет FortiClient | Проверяется до предложения установить root-службу; клиент ставится по правилам организации |
| FortiClient в нестандартной папке | GUI ищет зарегистрированный bundle ID и передаёт найденный путь; также поддержаны Applications/пользовательский Applications |
| Другой пользователь/UID | Пути службы вычисляются по UID; отчёты/профиль закрыты; восстановление чужого сеанса запрещено |
| Русские имена, пробелы, JSON BOM | Регрессионные тесты проходят; файл должен быть UTF-8 и обычным файлом |
| Нет прав администратора / корпоративный запрет | Нужна разрешённая установка помощника; мастер не обходит политику |
| Gatekeeper блокирует скачивание | Ожидаемо для ad-hoc; только штатное разрешённое исключение или подписанный выпуск, без отключения защиты |
| Wi-Fi/шлюз/DNS/VPN изменились, сон | Сеанс останавливается с попыткой точного отката; нужна новая подготовка |
| Captive portal, прокси, блокировка контрольных HTTPS | Подготовка может остановиться; VPN и DNS не перенастраиваются автоматически |
| Пересечение домашних и рабочих подсетей | Применение останавливается, если рабочий адрес уже не идёт в нужный VPN; не навязываем широкий частный маршрут |
| Незавершённый журнал, помощник пропал | Новый сеанс блокируется; требуется прежнее средство восстановления/администратор, журнал вручную не удаляется |

Не реализованы per-app VPN, split DNS/IPv6 и fail-closed рабочих приложений.
Экстремально длинный нестандартный TMPDIR может превышать лимит Unix socket;
перенос транспорта/миграция старого control socket требуют отдельной работы.
При аппаратном сбое/обрыве записи root-журнала автоматический откат не гарантирован.
