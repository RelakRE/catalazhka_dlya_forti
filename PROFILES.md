# Приватные профили

Публичный `split-config.json` — намеренно пустой шаблон, не готовая конфигурация.
Приложение не применяет маршруты до импорта непустого профиля.

Минимальный формат (адреса ниже вымышлены):

```json
{
  "schema": 1,
  "session_minutes": 0,
  "work_ipv4": ["10.77.1.20", "10.77.1.53"]
}
```

`0` означает отсутствие временного лимита. Допустимы также целые 1–480 минут.
Список — от 1 до 128 уникальных IPv4, без подсетей, IPv6, localhost,
link-local, multicast, команд, доменов и дополнительных полей.

Включите рабочие серверы, шлюзы удалённого доступа и корпоративные DNS.
Список должен соответствовать конкретному VPN; неизвестные дополнительные
зависимости могут потребовать нового профиля. Широкие частные подсети не
добавляются. Выбор адресов не ограничивает доступ только двумя приложениями.

Сохраните профиль в JSON и передайте коллегам через разрешённый внутренний канал.
Не публикуйте файл в репозитории, Releases или Issues. Пароли, PIN/MFA, токены
и настройки аутентификации FortiClient в профиль **не входят**.

Кнопка «Импортировать настройки…» проверяет файл до замены, атомарно сохраняет
его с правами 600 и сбрасывает старую подготовку. Некорректный файл не заменяет
прежний профиль. Активный сеанс блокирует импорт. Старый пользовательский
профиль не заменяется пустым шаблоном при обновлении приложения.

Приватные файлы держите в игнорируемом `private/` или вне каталога проекта.
Не заменяйте отслеживаемый `split-config.json` рабочими адресами перед коммитом:
Git не игнорирует уже отслеживаемые файлы. Для CLI можно использовать копию
исходников вне публичного checkout; предпочтителен импорт через приложение.
