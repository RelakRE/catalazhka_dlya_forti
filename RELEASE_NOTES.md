# Forti Split 1.4.1 — Intel Preview

- Отключение VPN в FortiClient и разрыв активного сеанса с подтверждённым
  откатом возвращают интерфейс к кнопке «Начать работу». Технический вывод
  больше не показывается как большая ошибка. Самостоятельного переподключения нет.
- Финальный результат передаётся отдельным структурированным сообщением,
  привязанным к PID собственного backend; канал полностью читается до обработки
  завершения. Ошибка отката остаётся блокирующей, даже при конфликтующем результате.
- Краткие сообщения операций, подробности по запросу в журнале настроек.
- Проверка доступа ждёт готовности launchd-службы после успешной установки.
  Повторная проверка не вызывает переустановку и новый запрос пароля.
  Причина отдельных прошлых ошибок ввода пароля по отчётам не доказана:
  приложение не получает пароль и не отличает неверный пароль от сбоя установки.
- Параллельное исправление Windows Companion 0.1.1: сброс старого статуса
  после пропажи VPN/маршрута, краткие ошибки и журнал в настройках. Windows
  не меняет маршруты и не использует системный запрос пароля нашего помощника.

## Обновление 1.4.0 → 1.4.1

Завершите старый сеанс, отключите VPN и выйдите из прежнего Forti Split.
Откройте новый пакет; профиль и настройки сохраняются. Root-модули и runtime
не менялись, поэтому текущий помощник 1.4.0 не требует переустановки.
Безопасная ручная приёмка: разрыв/отключение VPN → дождаться отката → снова
«Начать работу» → MFA в FortiClient → RDP/TrueConf. Реальный разрыв VPN и
системный запрос пароля не имитируются автоматическими UI-тестами.

# Forti Split 1.4.0 — Intel Preview

- Единая кнопка «Начать работу»: проверка доступа/сети, FortiClient и ожидание
  ручной MFA, автоматическое разделение, затем выбранные RDP/TrueConf.
- Одна кнопка и информативный статус на вкладке «Работа»; отдельная вкладка
  всех настроек и обслуживания. Мастер первого запуска предлагает отключаемые
  опции RDP/TrueConf. Существующие пользователи проходят новый этап один раз.
- Значок строки меню; закрытие окна скрывает его, не прерывая разделение.
  Выход через меню ждёт отката; неподтверждённый откат не маскируется завершением.
- Штатное скрытие FortiClient после подтверждения разделения, без запроса
  Accessibility/Automation. Это hide, не отключение VPN и не имитация кликов.
- Отключаемый запуск интерфейса при входе в macOS через SMAppService.
  Сам по себе он не включает VPN или маршруты.
- Отмена/ошибка/обрыв снимают intent. Приложения открываются один раз и только
  после active собственного backend PID. Запоздалый status старой операции
  не запускает следующую; RDP открывается через конкретную Windows App без shell.
- Собственная иконка и актуализированные инструкции из локальной 1.3.1.
- Удалены только две проверенно идентичные копии Python; библиотеки, stdlib,
  лицензии и основной интерпретатор сохранены. ZIP сжат сильнее без runtime-распаковки.

## Обновление и ограничения 1.4

Завершите старое разделение, отключите VPN и выйдите из старого Forti Split.
Распакуйте новый пакет; профиль сохраняется в Application Support. Новый runtime
меняет digest помощника: потребуется один системный запрос на его обновление.
После health мастер предложит новые опции. RDP-файл и программы не входят в пакет.
Для автозапуска при входе сначала перенесите пакет в постоянную папку «Программы».

Автоматические/UI/архивные проверки перечислены в VALIDATION.json. Настоящая
приёмка новой версии с VPN/MFA, RDP, звонком, скрытием конкретного Forti и login
item на пользовательском Mac ещё нужна. Это preview, не универсально проверенная
корпоративная поставка. Developer ID/notarization отсутствуют; не отключайте
Gatekeeper/SIP. DNS/IPv6, per-app isolation и fail-closed не добавлены.

# Forti Split 1.3.0 — Intel Preview

Предварительный Intel-выпуск 1.3.0. Релиз 1.2.0 остаётся доступен для возврата.
Сквозная приёмка новой GUI-сборки с настоящим VPN ещё не подтверждена.

## Изменения

- Системная светлая/тёмная тема, включая изменение оформления без перезапуска.
- Пошаговый мастер: профиль → системный доступ → сеть → VPN. Одно основное действие;
  нет лишнего подтверждения перед настоящим системным запросом пароля.
- Читаемый адаптивный интерфейс, прокрутка и отдельная скрытая группа обслуживания.
- Переносимые модель профиля, JSON и сценарий мастера; поздний выбор OS-адаптера.
  Windows пока отвечает явным отказом, а не выполняет команды macOS.
- Health привязан к версии установленного помощника. Подготовка/включение требуют
  успешной проверки; отсутствие FortiClient/другой VPN/проблемы восстановления видны.
- Ограничения времени IPC/status, строгий JSON, чтение install payload через
  дескрипторы, сохранение busy до окончания живого отката, закрытые пользовательские
  каталоги и атомарное сохранение.
- Проверка источников сборки и привязка UI-доказательств к конкретному executable.
- Применимые практики, внутреннее ревью и матрица переносимости:
  STANDARDS.md, REVIEW.md, PORTABILITY.md.

## Переход с предыдущей версии

1. Штатно завершите активное разделение и дождитесь отката.
2. Откройте новый отдельный Intel-пакет. Существующий пользовательский профиль
   сохраняется, повторный импорт обычно не нужен.
3. На этапе доступа обновите помощник через системное разрешение macOS.
   Новая версия его модулей требует однократного подтверждения администратора.
4. Дождитесь health, подготовьте сеть без VPN, подключите FortiClient с MFA
   и включите разделение. Во время первого реального теста держите отчёты доступными.

## Проверки и ограничения

Результаты автоматических, UI и архивных проверок сохраняются в VALIDATION.json.
Работа нового пакета с настоящим VPN, звонком/RDP, сном и другим Intel Mac
ещё требует ручной приёмки. Проверки не выполняют настоящие маршрутные изменения.

По-прежнему только Intel; готового Windows/Apple Silicon-порта нет.
DNS/IPv6 не разделяются, per-app isolation и fail-closed не реализованы.

Ad-hoc подпись — без Developer ID и нотариального заверения Apple. macOS может
запретить скачанный пакет. Не отключайте Gatekeeper/SIP; нужна разрешённая штатная
процедура или подписанная поставка. Профили/сырые отчёты не публикуются.
